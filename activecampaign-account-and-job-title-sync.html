ActiveCampaign Account & Job Title Sync

Two Supabase edge functions that link contacts to their org account and fill contact job titles

Many leads in our sales tables have an ActiveCampaign (AC) contact whose Job Title is blank. This automation finds each person's job title and writes it into AC — but only when the field is currently empty, so a human-entered title is never overwritten. It runs as two small functions you call one after another from n8n: the first attaches a company account to contacts that don't have one and then fills the title, and the second fills titles for contacts that already have a company attached.

What it does

It works across four lead tables in the Supabase project MAGTestProject: manually_found_leads, ai_scraped_soc_med_leads, manually_found_cold_leads, and ai_verified_cold_leads.

For each lead it will:

  • Find the person's job title via an OpenAI web-search-grounded lookup that verifies the current title from public sources — and returns nothing when it can't confirm, so it never guesses.
  • Write that title into the contact's AC record — only if the AC title is empty. If a title is already there, it's left untouched and the row is marked as manually set.
  • When the contact isn't attached to a company in AC, attach the matching company account first, then fill the title.

A key detail about AC: there is no standalone "Job Title" field. A contact's job title lives on the link between the contact and their company account. So a contact with no company attached has nowhere to store a title — which is exactly what the second function fixes.

The two functions — run in order

1. ac-account-contact-sync (runs first)

Handles contacts that don't have a company attached in AC. It finds them from our local mirror of AC contacts: any lead whose contact has no company (its orgid is '0'), plus any row previously flagged ac_account_needs_update = true. Contacts we've already linked are skipped.

  • Looks up the lead's org (company name) among AC's existing company accounts.
  • If it finds an exact match, it attaches that company to the contact, marks ac_acc_linked = true, then fills the job title and stamps the date.
  • If the contact already has a company (linked in the meantime), it just fills the title when it's blank.
  • If the company isn't in AC (or the name doesn't match), the row stays flagged for someone to set the company up manually.
  • Contact not in AC → leave it for a later run.

2. ac-poc-position-sync (runs second)

Handles contacts that already have a company attached in AC:

  • Title already set → leave AC alone, mark the row job_title_is_manually_set = true.
  • Title empty → find it and write it, then stamp the update date.
  • No company attached → flag the row ac_account_needs_update = true so the first function links it on the next cycle (no enrichment spent here).
  • Contact not in AC → skip and leave it for a later run.

The hand-off is clean: if the first function attaches a company but the title can't be found that run, the second function picks the title up on the next cycle.

How it's built

Architecture

The whole thing is two Supabase Edge Functions (small serverless scripts) that read the lead tables, talk to two outside services, and write results back. End to end:

  • Lead tables (Supabase / Postgres) — the source of leads and the place every result is recorded (job title found, whether AC was updated, whether a company needs attaching, etc.).
  • Edge function reads eligible rows — each run selects a capped batch of rows still needing work, ordered oldest first.
  • ActiveCampaign API (checked first) — the function looks up the contact and whether a company is attached before doing any enrichment, so it never spends credits on a lead it can't update.
  • OpenAI web search (enrichment, only when needed) — when there's a real place to write an empty title, it asks OpenAI's web-search tool to verify the person's current title from public sources (LinkedIn, the company's own site, press releases). It returns nothing when it can't confirm, so a wrong title is never invented, and unresolvable leads stop being looked up after a couple of attempts to avoid wasted cost.
  • Write back — the title is written to ActiveCampaign, and the outcome is recorded on the Supabase row. A status column is only set after the matching external call succeeds, so a mid-run failure just leaves the row to retry — no double writes.
  • Orchestration (n8n) — an n8n workflow calls function one, then function two, on a schedule. Each function returns a JSON summary (tagged with its name) for the workflow's logs.

Tech stack

  • Supabase — Postgres database (the lead tables) and Edge Functions runtime.
  • Deno / TypeScript — the language the edge functions are written in.
  • ActiveCampaign API — where contacts, company accounts, and job titles live.
  • OpenAI (Responses API, web search) — the enrichment service that verifies job titles from public sources.
  • n8n — the workflow tool that runs the two functions in sequence.
  • Google Secret Manager — the source of truth for the API keys, mirrored into Supabase's secret store.

Running it

Each function accepts the same options on the request:

  • ?sync=1 — run immediately and return a summary (otherwise it runs in the background).
  • ?limit=N — how many rows to process this run (default 10).
  • ?email=<address> — process just one lead by email (handy for re-processing a single record).
  • ?title=<text> — set a specific title by hand instead of searching (still never overwrites an existing AC title).

In normal use, n8n calls ac-account-contact-sync first and ac-poc-position-sync second, each with a sensible limit. The returned summary counts what happened: companies attached, titles written, titles already set, rows still needing a company, and so on.

Good to know

  • Existing titles are safe. The automation only fills a blank Job Title — it will never overwrite one that's already there.
  • Company matching is deliberately strict. A company is only attached when the lead's org exactly matches an AC account name (ignoring accents and spacing). Typos or variant names (e.g. a misspelled company) are left for a person to handle, so a contact is never attached to the wrong company.
  • Enrichment isn't perfect. The web-search lookup only returns a title it can verify from public sources, so a specific person isn't always found; those rows keep their title blank and are retried later, up to a capped number of attempts so an unresolvable lead doesn't keep costing money.
  • Cold leads not yet in AC are skipped and retried once they exist in ActiveCampaign.
